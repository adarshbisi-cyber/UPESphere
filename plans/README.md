## Recommended execution order

1. **005 first, always.** It touches 26 files purely mechanically (swap a literal array for an import). Landing it before any other plan means 001–004 and 006–015 can cite `EASE_OUT` directly instead of the raw array where relevant, and avoids merge conflicts from two plans touching the same easing literal in the same file. If executing plans out of order, any plan whose Target shows a bare `[0.22, 1, 0.36, 1]` array should use `EASE_OUT` instead once 005 has landed.
2. **001, 002, 003, 004** (the four HIGH-severity table findings) — independent of each other and of 005 beyond the note above, safe to run in any order or in parallel across separate files.
3. **011** — touches `FinalStep.tsx` (also touched by 015) and overlaps file-wise with 001's calculator fixes (`PassCalculator.tsx`, `AttendanceCalculator.tsx` — see 011's explicit note on checking whether 001 already removed the sites it targets). **Run 011 after 001** to avoid 011 editing code that 001 is about to delete.
4. **015** — touches `FinalStep.tsx`'s checklist section; **011 touches the same file's icon** (a different, non-overlapping block). No hard ordering requirement between them, but running 011 first (per point 3) means 015 lands on top of the already-fixed icon scale, avoiding any confusion about which scale value is "current."
5. **006, 007, 008, 009, 010** — independent of everything else, any order.
6. **012, 013, 014** — independent additive plans, any order, but note 014 is the only structurally invasive plan (merges two early-returns into one conditional render per file) — review its diff more carefully than the others.

## Dependencies summary

- **005 → (001, 002, 003, 004, 006, 007, 008, 009, 010, 011, 012, 013, 014, 015)**: soft dependency (token availability), not a hard blocker — every other plan's Target still specifies the literal array as a fallback if 005 hasn't landed yet.
